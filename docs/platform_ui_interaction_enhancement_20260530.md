# Winnsen Structure Agent Studio 平台交互增强说明

日期：2026-05-30

## 当前结论

这份文件记录的是早期平台交互方案。当前 16029 主线已改为“结构工程辅助基础模型”：输入客户柜体宽度、深度和门数后，只解析到已验证的 SolidWorks 原生配方；未验证规格不会回落到旧生成器。

当前可用边界：

- 工程师登录后可以下载 V35、V36、V37 三个已验证原生基础模型。
- 平台新增了柜门提示词工作台，用于把自然语言整理成门板、门高、锁具、铰链、加强筋、开孔等参数草案。
- 平台新增了浏览器内参数化预览，用于确认门序、门板比例和五金意图；左右列不同门高序列（例如左 6/4/2、右 2/4/6）可以分列显示。
- 平台新增了结构工程师交互区，用于整理审核点、截图路径、模型路径、验证记录和可复制的审核提示词。
- Studio 前台参数页会调用 `tools/locker_16029_native_generator.mjs` 解析客户参数，并由 `tools/process_16029_native_generation_request.mjs` 输出可审计记录。
- 命中 V35/V36/V37 精确规格时直接绑定对应原生基础模型；没有精确配方时明确返回“尚未完成原生配方验证”。

当前尚未完成的能力：

- 尚不能对任意宽度和任意门数组合即时生成同等质量的原生模型。
- 尚不能自动完成项目工程图、展开图、公差或喷涂后间隙等深化内容。
- 锁孔、铰链孔、插销和加强筋等项目细节仍由结构工程师在基础模型上继续处理。
- 浏览器预览只是参数化参考预览，不是真实 SolidWorks/STEP 几何预览。
- 下载结果包是结构工程辅助基础模型，供结构工程师继续深化。

## 已实现入口

- `apps/web/src/App.tsx`
- `apps/web/src/App.css`
- `tools/serve_16029_review_downloads.mjs`

## 平台整理原则

- 当前入口统一标注“结构工程辅助基础模型/供结构工程师继续深化”。
- 运行数据不进入 Git 主线，`data/native_model_requests/` 仅作为本机参数匹配记录目录。
- CAD 生成物、Pack and Go、历史试错包继续留在忽略范围内，不混入代码提交。
- SolidWorks 2020 仍是当前工程师审核软件主线。
- 已删除的 FreeCAD scaffold 和旧通用生成队列不得重新接入 16029 当前入口。

## 后续扩展原生配方的路线

1. 参数解析输出稳定 schema：柜体尺寸、门数、门序、门板规格和机械锁舌要求。
2. 新组合必须明确绑定 V35/V36/V37 中的已验证原生宽度族和门数组合，不允许调用旧通用生成器。
3. 原生构建必须带一门一锁孔、层板/横档、引用闭合、重建保存重开和异地解压复开证据。
4. 只有上述证据完整后，才能把该组合加入可下载配方表。
5. 工程师下载后继续完成订单相关的材料、板厚、工程图、BOM 和工艺细节。
