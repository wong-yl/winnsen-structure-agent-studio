# 门板展开准备与 DXF 导出边界

Continue19 已取得左门 DXF 的尺寸、毫米单位和 12 条折弯线证据；导出调用链仍 FAIL，右门新 DXF 未取得。不能把一个文件内容通过扩大成完整导出流程通过。

## 已证实的展开准备

1. 绑定模型文件、配置和 SHA；将独立测量副本及其依赖临时设为 Windows 只读，并核对 SolidWorks 的实际只读状态。
2. 在新会话中，从已有 `Default` 切到已有派生配置 `DefaultSM-FLAT-PATTERN`，只在内存启用绑定的 `平板型式1` 与它的 12 个 `UiBend` 子步骤。没有启用这些子步骤时，即使配置名称含 FLAT-PATTERN，也不能据名称认定已展开。
3. 用原生固定面绑定当前唯一钣金实体，核对厚向、双平行面、配置操作范围与生效补偿，再量面内尺寸。
4. Continue19 左门两会话均量到 `473.4000000000001×507.6499999999998 mm`，厚向 `0.7999999999999674 mm`，上述原生几何与补偿检查通过。右门本轮没有重新运行，沿用 Final13 的原生展开证据。

Continue18B 的门板 DXF 为 `437×471.25 mm`，两轴各小 `36.4 mm`，其 FAIL 原样保留。API 返回成功或派生配置名称正确，都不能替代实际外轮廓比较。

第二条官方示例把准备 API 与导出格式的 `SaveAs` 联用；后者与保存原生模型不同，必须如实计数。本轮未到 `SaveAs` 调用点，却观测到文件，必须同时保留官方流程和本机实际结果，不能按预想抹去文件。旧枚举 `None=0/RemoveBends=1` 与 `ExportToDWG2` 的钣金位选项 `1/5` 不可混用。

收尾只读解析左门文件：外闭环 `473.4×507.65 mm`，两轴偏差均 0；`INSUNITS=4`；80 实体（77 LINE、2 CIRCLE、1 ARC），12 条 `CENTERX2` 与 68 条 `Continuous` 分开。将原生 `IsBendLine=true` 的 12 组端点，用单位尺度的轴向反射/置换和整体平移对照，全部与这 12 条 DXF 线吻合。没有缩放、按公式拟合、改图层或写回 DXF。对称性没有解决制造视图手性，仍待确认。

初次只看 API 事件或导出进行中的目录会误报“没有文件”。最终应在 CAD 退出后核对实际目录，再绑定路径、时间、SHA、单位和几何；不能只根据没有成功 event 推断文件不存在。

## DXF 验收应分开记录

- 文件产生：API 原始返回、异常、输出路径、文件大小及 SHA。
- 几何与单位：只读解析真正外闭环，要求 `473.4×507.65±0.5 mm` 和 `INSUNITS=4`，不能只看全部图元包围范围。
- 折弯区别：由原生图层/线型及 API 端点对应，或只改变折弯选项的导出文件逐实体差分证明。不能只因两边都为 12 条就说已绑定；本轮已完成单位尺度端点集合核对。
- 健康与保护：`warnings=2` 原值保留，原零 warning 健康门未通过；不能因几何正确而改写。关闭后核对所有源、依赖和副本 SHA、属性恢复、锁和进程。
