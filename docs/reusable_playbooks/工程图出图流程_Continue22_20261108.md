## 新建图纸的类型陷阱

模型和工程图不是同一文档类型。Continue21 在新建 Drawing 后，通用审计仍读取零件式 ActiveConfiguration，触发 NullReferenceException；原生展开视图 API 尚未调用。应只对精确冻结的模型读取活动配置，刚创建的 Drawing 由对象身份或预声明图纸路径审计，图纸活动配置字段保留 null。不能伪造 Default，也不能放行任意未知文档。

## 关闭 CAD：请求与退出分开验收

正常会话应在原连接仍有效时，无保存关闭模型和临时图纸，再请求 CAD 退出。关闭/清理过程不要依赖已导致审计失败的同一 getter。退出必须以精确 PID、启动时间和 EXE 的进程消失证明；COM 失联或窗口枚举为空都不能代替。

Continue22 明确接管 Continue21 的 PID18060，先核对启动 UTC ticks=639297378483495578 和 EXE D:\SOILDW~1\SOLIDW~1\SLDWORKS.exe，2026-11-08 21:05:26 +08:00 仅发一次 taskkill.exe /PID 18060（不带 /F）。命令 exitCode=0，原文 SUCCESS: Sent termination signal to the process with PID 18060. 这只证明发出了请求。

截至21:07:27，等待约120秒后 CAD 仍在，sldProcMon PID10512 的父进程仍为18060，因此保留；sldworks_fs PID20408保留。未强杀、未启动第二CAD、未继续出图。未保存文档提示、隐藏窗口或COM状态导致驻留的具体原因未证明，不能猜测。

父CAD未退出时，不清monitor。只有父进程确已消失、monitor的PID/启动时间/命令行及会话归属都吻合时，才可清理被接管会话的孤儿monitor。不得扩大到同名服务或其它任务进程。
