# 室外柜运行依赖隔离修复

本目录对应 2026-11-09 工作台失败任务 `OUT22057-8bdbcd9b-3e71-4ae1-bea6-4c6b96940ff2`。

## 原因与改动

原 v16 的 `run_native.mjs` 只需要共享 CAD 占用锁，但通过导入整个室内柜 worker 带入室内柜任务、发布、物理验收等模块。旧 qualification 对这条完整导入链做文件哈希绑定。三个室内柜模块更新后，户外任务在 `portal_generate.py` 第33行被阻止，尚未开始原生建模。

`runtime_v17` 新增独立锁模块，沿用原锁函数、锁目录、令牌、心跳、存活进程检查；与现有室内柜互斥测试已通过。布局校验模块在新目录内固定；原生 EXE/DLL、源模型清单、几何审计、尺寸范围、逐任务验收保持不变。旧 v16 不修改，共享室内代码不回退。

唯一其它变更为本运行副本的 CAD 清理脚本：原脚本强制终止，现仅验证 PID/启动时间/EXE 后等待自然退出，90秒未退则失败保留现场。不得强杀或忽略退出失败。

`qualification.json` 继承原几何资格证据并明确记录运行依赖变更及其范围；本次新任务必须通过原有原生生成、独立回读和所有几何审计才能发布，不能用继承资格或静态测试替代任务实跑。

## 证据与维护

- `dependency_drift.json`：三个旧绑定差异。
- `original_identity.json`：原 v16 支持文件、源模型及外部依赖的修复前 SHA。
- `runtime_preflight.json`：完整哈希、锁互斥、存活进程与令牌所有权检查。
- `hash_rejection_tests.json`：篡改运行支持/外部证据时拒绝启动 CAD。
- `release_gate.before.json` / `release_gate.candidate.json`：发布入口改动前后配置。
- `runtime_v17/evidence/portal_5a052ec02402432b9bd6ef78117f37d4_*`：本次同参数真实任务证据。

后续室内柜更新不再进入户外生成器的导入链。若修改户外生成器、锁协议或审计本身，必须建立新的版本与验证记录，不得直接刷新哈希冒充验证。运行目录不可清理，工作台新任务依赖它。

## 回退边界

仅在队列无运行任务时，比较现行入口与 candidate 后可恢复 `release_gate.before.json`。这会恢复旧入口及其已知依赖漂移失败，不是可用性修复；不覆盖任务、模型或证据。不要删除任何正在运行的目录。
